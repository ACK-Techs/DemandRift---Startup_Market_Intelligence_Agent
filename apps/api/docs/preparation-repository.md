# BE-02 hazırlık repository alt teslimi

`PreparationRepository` yalnız çözülmüş UUID owner+project bağlamıyla çalışır. Proje/araştırma/fikir/plan kimliğini server üretir; çağıran yeni snapshot'a başka bir logical ID veremez. Aynı araştırmanın brief sürümü research row lock; bütün projenin plan sürümü project row lock ile monoton artar. Transaction içinde HTTP/model/worker çağrısı yoktur. İsim ve original idea whitespace/Unicode ile aynen saklanır; başka original idea aynı araştırmaya yazılamaz. Read selector owner/project/research+ID+sürüm ister; yabancı ve bulunmayan kayıt aynı `RecordNotFound` olur.

Brief ve plan immutable typed snapshot'tır. Yeni plan eski brief içerik snapshot'ını aynen alır. Tam source/query profilleri yalnız validated ResearchPlan array'lerinden aynı transaction'da türetilir. Readback full Pydantic doğrulaması, row identity/created_at/version parity, canonical fingerprint ve child setlerinin exact equality'sini kontrol eder. Eksik/ekstra/bozuk source/query child kayıtlarındaki veri UI'ya plan diye gönderilmez. JSON array sırası plan snapshot'ında korunur; relational child lookup sırası anlam taşımaz. Decimal cost string, null/unknown ve köken alanları dönüştürülmez.

Fingerprint `plan_fingerprint` dışındaki bütün typed serialization içeriğinin UTF-8/sorted-key/compact JSON SHA256'ıdır; original idea, owner/project/research, ID/sürüm/zaman, kullanıcı koşulları, query/source/budget/version/status dahil. Onay bekleyen planın status/timestamp/sürüm değişince fingerprint de değişir. `approve_plan` tam seçilmiş ID/sürüm/fingerprint ve en son araştırma planına bağlıdır. Bekleyen plan ayrıca en son brief kimliği/sürümünü kullanmalıdır; kullanıcı koşulları yeni brief ile değiştiyse eski plan yeniden oluşturulmadan onaylanamaz. Project ardından research row lock, brief yazımı ile onayı aynı transaction sınırında sıralar; eşzamanlı yeni brief commit ederken onay bekler ve sonra stale planı reddeder. Confirmed brief ve canonical confirmation kuralları sağlanmadan onay kayıtlanmaz. İnsan onayı yeni confirmed plan sürümü ve ona bağlı ApprovalRecord'u atomik oluşturur; eski awaiting_user snapshot değişmez. Confirmed tuple'ın tekrar okunması daha yeni brief bulunsa da aynı tarihsel kaydı döndürür; bu yeni araştırma start yetkisi değildir. Eski awaiting_user tuple'ın tekrarı stale error olur; HTTP idempotency BE-04'tedir.

Bu repository API/auth/insan onay ekranı veya araştırma start değildir. Trusted human event handler bağlantısı BE-03/07'de; worker/start/bütçe BE-04/05'te ayrı zorunlu kabul kalır. Evidence/segment/claim/citation/bundle/report/gap typed persistence, global logical-ID scope anchor ve graph membership sealing BE-02'nin sonraki migration/repository alt teslimidir. Mevcut foundation FK/immutable/RLS geçerlidir; repository readback kontrolü doğrudan SQL için gelecekteki complete graph DB constraints'in yerine geçmez. Bu teslim BE-02 üst paketini kapatmaz.

Gerçek PostgreSQL testleri çoklu bağlantıdan eşzamanlı allocator, rollback, yabancı owner/project/research selectors, nonempty source/query roundtrip, stale confirmation, exact original ve immutable history'yi doğrular. Engine dispose/fresh connection persistence geliştirme kapısıdır; controlled server restart ve exact Linux/PostgreSQL CI üst paket kapılarıdır. Production restore/rollback ve bütün87 mandatory senaryo ayrıca zorunludur.
