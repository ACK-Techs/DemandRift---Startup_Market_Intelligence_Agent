# Typed evidence repository

`EvidenceRepository(database, resolved_user_uuid, resolved_project_uuid)` exposes one owner/project context. `get(research_id, kind, identity, version)` requires an explicit version for documents, claims, bundles, reports and gaps; versionless records reject invented version arguments. Foreign and absent identities produce `RecordNotFound` without disclosing stored payloads.

`transaction(research_id)` locks project then research and publishes a complete graph in one PostgreSQL transaction. It performs no HTTP, provider or worker operation. `put_run` atomically keeps the execution DTO array and mutable execution records aligned. Artifact/document/segment, claim/citation, source, bundle, report and gap parent tuples retain their selected scope/version. A midway error rolls back the graph.

Writes and reads revalidate canonical models and compare known plan/brief metadata with the original selected run context, including nested envelope objects. Parent document/bundle/report IDs without wire versions require explicit internal pins. Reads reject self/future parent selections rather than choosing the latest version. Graph constraint errors become the generic `StoredSnapshotError`; SQL details and parameters are not returned as the storage error message. Reads also recheck stored document/artifact URL and capture time, UTF-8 full-text/segment hashes, selected segment bounds and validated quote text. Claim/source/bundle/report/run reads traverse their explicit selected content; one read caches repeated snapshots and rejects cycles. A pending/rejected mismatching quote remains audit data and never becomes validated. Immutable retries recheck committed stored content before returning success. An identical new snapshot created by the same writer can be retried while its children are still pending; its body and explicit pins must match. Before commit, pending associations are inserted, all deferred native constraints are made immediate, and every touched snapshot passes the complete selected-content read. Missing or corrupt graph members roll back the transaction.

Source report claim versions, bundle document/gap versions, report gap versions and parent/previous versions must be supplied explicitly. Retry of the same immutable DTO and identical internal selections is harmless; a changed body or selection requires a new snapshot version or, for versionless records, a new UUID. `selections` exposes internal pins separately from the canonical wire object.

This repository currently binds the original approved plan. BE14 will add approved plan admissions, actual execution versions and historical projections while retaining the same run identity and global budget. The original run lifecycle values are persistence primitives; authentication, idempotent start, lease/worker recovery, budget accounting, external raw-body truth and policy acceptance have their separate roadmap gates.

Tests use synthetic canonical `.invalid` fixtures. Their stamps, counts and usage are test expectations. Full A/B historical roundtrip, foreign lookup, metadata lies, hidden parent corruption, generic graph errors, exact immutable retry pins, restored content corruption across direct and selected parent reads, pending/rejected quote audit and atomic rollback run on real disposable PostgreSQL. This does not complete the mandatory 87 product scenarios.
