# FE-04 proje çalışma alanı

`/projects` kanonik Session içindeki owner bağlamıyla `GET /api/v1/projects` ve `POST /api/v1/projects` tüketir; `/projects/{projectId}` kanonik `GET /api/v1/projects/{projectId}` detayını gösterir. Proje UUID'sini backend üretir. Cookie aynı origin `/api/backend` üzerinden gönderilir; create CSRF değeri yalnız doğrulanmış oturumdan alınır. Serbest upstream URL veya model credential bu modüllerin girdisi değildir.

`Project`, `ProjectPage` ve `ProjectCreate` aynı üretilmiş kanonik wire schema üzerinden doğrulanır. Liste nested owner UUID'lerini, detay owner ve istenen project UUID'sini denetler. `200` list/detail ve `201` create makbuzu ayrı beklenir. Liste 25 kayıtlık sayfadır; opaque server cursor aynen aktarılır ve bir sonraki sayfa mevcut sayfayı değiştirir. Görünen kayıt sayısı yalnız okunan sayfanın uzunluğudur; toplam proje/araştırma sayısı türetilmez. Yinelenen UUID, archived liste kaydı, boş veya aynı cursor, sınır dışı kayıt sayısı ve beklenmeyen page limit sözleşme hatasıdır. Detayda archived proje gerçek kaydı olarak ayrıca gösterilebilir.

Owner bağlı store yalnız bellektedir. Session değişince, logout/expiry veya component unmount olduğunda private kayıtlar, token ve pending request'ler temizlenir; geç gelen önceki owner yanıtı generation kontrolüyle reddedilir. Detay URL'sindeki UUID değişince eski proje gösterilmez; yeni scoped GET beklenir. Authenticated session olmadığı sürece proje kontrolleri ve kayıtlar görünmez. Protected401 bütün proje cache'ini kaldırır ve açık session kontrolü ister. Bu bounded teslimde global account store/topbar'ın aynı401 nedeniyle anında CAS invalidation yapması henüz yoktur; ayrı auth consumer integration child bu sınırlamayı kapatacaktır. 403/404 veya network belirsizliği logout anlamına gelmez.

Project name 1–200 Unicode karakter ve nonblank kanonik girdi kontrolünden geçer; trim/case değişikliği olmadan gönderilir. Pending store kilidi ikinci create POST'u engeller; başarılı submit formu temizler. `201` owner/name/archive makbuzu doğrulanmadan başarı bağlantısı çıkmaz. Known create kaydı ayrı receipt'tir; server listesine kayıt eklenmiş gibi bir sayfa üretilmez. User listeyi GET ile yeniler veya dönen güvenilir UUID detayına gider.

Network/timeout/5xx veya bozuk successful receipt sonrası create sonucu `unknown` olur. Aynı view'de yeni POST durur; “Check saved projects” yalnız açık GET yapar. Listede aynı isimli kayıt bulunması önceki POST sonucunu benzersiz biçimde belirlemez; create receipt veya confirmed UUID uydurulmaz. Kullanıcı kayıtları okuduktan sonra “Continue after reviewing list” açık ayrı-create niyetiyle formu açabilir. Önceki sonucu belirsiz olan POST otomatik yeniden gönderilmez. Backend create route bu dilimde idempotency key desteği sağlamaz; tarayıcı reload/navigation veya yeni session ardından eski bilinmeyen POST'u kalıcı biçimde uzlaştırma parent integration'da ayrıca değerlendirilir. Bu store backend transaction/idempotency yetkisinin yerine geçmez.

Loading, boş sayfa, auth/expiry, permission, not_found, unavailable, validation, rate_limit, contract ve unknown ayrı görünür. Pozitif kanonik Retry-After süre boyunca yeni isteği durdurur; sıfır manuel yeniden denemeyi açık bırakır, otomatik retry yoktur. Alan hatası input ile `aria-describedby` üzerinden bağlıdır. Scoped layout ilk keyboard linkiyle proje içeriğine atlar; semantic form, alert/status ve minimum44px kontroller korunur. Mevcut DemandRift tasarımı yeniden tasarlanmaz.

Research history API henüz bu view'e bağlanmadığından detay “Research history unavailable” gösterir. Project yaratmak research run başlatmaz; fake araştırma sayısı, ilerleme veya karar sonucu yoktur. Backend brief/research contract teslimi geldiğinde ayrı tüketici işi bu alana bağlanacaktır.

`npm run test:projects` fixture HTTP üzerinden scope/receipt/Unicode/pending/unknown/pagination/error/owner değişimi/deadline kontrolleridir. Typecheck ve lint geliştirme kapılarıdır. Bounded Playwright desktop/mobile/keyboard ve list/create/detail/logout/unknown/error akışlarını açıkça mocked API yanıtlarıyla test eder; gerçek Hetzner session/proxy/cookie/CORS kanıtı değildir. Parent FE-04 gerçek uçtan uca kabulü ve final87 zorunlu senaryolar açık kalır. Frontend deployment, key erişimi ve sağlayıcı çağrısı yapılmaz.
