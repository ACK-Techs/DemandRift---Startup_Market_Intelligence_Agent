# DemandRift dört servisli runtime

`runtime.compose.yml`, mevcut `demandrift-api` projesinin API/worker/PostgreSQL16/Redis7.4 genişlemesidir. Mevcut health-only `compose.yml` yerine kurulması kabul edilmiş exact SHA, bağımsız review/verify, Linux CI ve güvenilen deploy helper'ın migration/readiness/rollback uyarlaması tamamlanınca yapılır. Bu dosyanın varlığı kurulum kanıtı değildir.

API yalnız `127.0.0.1:18082` üzerinde kalır. Frontend local `http://127.0.0.1:3100`, sabit SSH tüneli ve aynı origin `/api/backend` rewrite ile bağlanır. Secure session ve CSRF politikası korunur; gerçek browser kabulü ayrıca yapılır. Frontend hosting tetiklenmez.

DB ve Redis yalnız private `demandrift-api_data` internal ağına bağlıdır; host/public portları yoktur. API/worker bu ağa ve projeye ait mevcut egress ağına bağlanır. Mevcut `demandrift_api_artifacts` volume korunur; yeni DB ve Redis volume'ları projeye özgüdür. Rootfs read-only, uygulamalar UID10001, DB/Redis UID999, tüm capabilities kapalıdır. Restart, CPU/memory/PID, tmpfs ve log rotasyonu sınırları dosyada sabittir. AOF/Redis ACL yapılandırması host private `redis-config` dosyasında kurulur ve kabulde içerik güvenli metaveri kontrolleriyle doğrulanır.

Host secret dosyaları `/etc/demandrift/runtime` altında oluşturulur. Uygulama DSN/broker/model dosyaları UID10001 ve0400; PostgreSQL/Redis özel dosyaları UID999 ve0400 olmalıdır. Migration admin DSN yalnız operations one-shot servisine UID10001/0400 ile verilir; API/worker admin secret almaz. Compose file-backed secret `uid/mode` dönüşümüne güvenilmez: kaynak dosyanın gerçek UID, private mode, regular single-link/no-symlink olması ve container içindeki aynı özellikler kurulmadan önce/sonra doğrulanır. Secret değerleri Git, image, frontend, komut argümanları ve loglara yazılmaz.

İlk PostgreSQL startup'ta ayrı `demandrift_app` LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS rolünün güvenilen bootstrap ile oluşturulması gerekir. Bootstrap henüz bu Compose dosyasının bir parçası değildir; role hazır olmadan migration çalıştırılmaz. Eski001–008 migration geçmişi değişmez; migration uygulama grant'lerini sağlar. Migration başarıyla bittiğinde API/worker başlatılır, `/ready` ve gerçek auth/project/preparation akışları doğrulanır. Worker handler henüz unconfigured olduğundan runtime ready araştırma pipeline'ının tamamlandığı anlamına gelmez.

PostgreSQL local/host başlangıç authentication'ı SCRAM'dir. Container OS kullanıcısı `postgres`, DB admin kullanıcısı `demandrift_admin` olduğundan local peer eşleştirmesi init script'inin bağlantısını engeller. [Resmi PostgreSQL Docker entrypoint'i](https://github.com/docker-library/postgres/blob/master/16/bookworm/docker-entrypoint.sh) init sırasında FILE password'u alıp local authenticated setup için kullanır. Redis health password'u argüman yerine stdin'den alır; [Redis7.4 CLI kaynağı](https://github.com/redis/redis/blob/7.4/src/redis-cli.c) `--askpass` intake'ını tanımlar. Host gerçek init/auth/health davranışı kurulum kabulünde ayrıca çalıştırılır.

Dağıtım helper'ı henüz API-only davranır. Bu dosya o helper ile doğrudan gönderilmez: migration öncesi backup/quiesce, uyumlu image seçimi, admission kapıları ve hata sonrası güvenli toparlama ayrı OP-04 teslimidir. Migration downgrade veya head007 imajına otomatik dönüş, yeni head008 güvenlik koşulunu bozar ve rollback olarak kullanılamaz. DB/raw/spool restore ve gerçek container restart/recovery kabulü OP-05/OP-06'da açık kalır.
