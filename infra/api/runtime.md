# DemandRift dört servisli runtime

`runtime.compose.yml`, mevcut `demandrift-api` projesinin API/worker/PostgreSQL16/Redis7.4 genişlemesidir. Mevcut health-only `compose.yml` yerine kurulması kabul edilmiş exact SHA, bağımsız review/verify, Linux CI ve güvenilen deploy helper'ın migration/readiness/rollback uyarlaması tamamlanınca yapılır. Bu dosyanın varlığı kurulum kanıtı değildir.

API yalnız `127.0.0.1:18082` üzerinde kalır. Frontend local `http://127.0.0.1:3100`, sabit SSH tüneli ve aynı origin `/api/backend` rewrite ile bağlanır. Secure session ve CSRF politikası korunur; gerçek browser kabulü ayrıca yapılır. Frontend hosting tetiklenmez.

DB ve Redis yalnız private `demandrift-api_data` internal ağına bağlıdır; host/public portları yoktur. API/worker bu ağa ve projeye ait mevcut egress ağına bağlanır. Mevcut `demandrift_api_artifacts` volume korunur; yeni DB ve Redis volume'ları projeye özgüdür. Rootfs read-only, uygulamalar UID10001, DB/Redis UID999, tüm capabilities kapalıdır. Restart, CPU/memory/PID, tmpfs ve log rotasyonu sınırları dosyada sabittir. AOF/Redis ACL yapılandırması host private `redis-config` dosyasında kurulur ve kabulde içerik güvenli metaveri kontrolleriyle doğrulanır.

Host secret dosyaları `/etc/demandrift/runtime` altında oluşturulur. Uygulama DSN/broker/model dosyaları UID10001 ve0400; PostgreSQL/Redis özel dosyaları UID999 ve0400 olmalıdır. Migration admin DSN yalnız operations one-shot servisine UID10001/0400 ile verilir; API/worker admin secret almaz. Compose file-backed secret `uid/mode` dönüşümüne güvenilmez: kaynak dosyanın gerçek UID, private mode, regular single-link/no-symlink olması ve container içindeki aynı özellikler kurulmadan önce/sonra doğrulanır. Secret değerleri Git, image, frontend, komut argümanları ve loglara yazılmaz.

`operations` profilindeki `migrate`, `python -m app.runtime_migrate` çalıştırır. Yalnız bu işlem admin ve application DSN FILE'larını birlikte okur; application FILE yolu `DEMANDRIFT_APPLICATION_DATABASE_FILE` ile verilir. Broker veya Gemini secret'ı almaz. Strict bootstrap config iki bağlantının aynı açık database/host/port/options kapsamını ve ayrı admin/application kimliğini doğrular; environment DSN fallback kullanmaz. Config yükleme SQL çalıştırmaz. Release içindeki sabit `alembic.ini`/`migrations/versions` ve tek doğrusal001–008 zinciri doğrulanır; bilinmeyen, ilerideki veya çoklu mevcut head, role yazılmadan reddedilir.

Güvenilen bootstrap ayrı `demandrift_app` LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS NOREPLICATION rolünü oluşturur veya mevcut rolün kısıtlarını ve SCRAM password eşleşmesini doğrular. Güvensiz mevcut rol sessizce benimsenmez, düzeltilmez veya password'ü değiştirilmez. Ardından advisory transaction lock altında canonical migration'lar yalnız `REQUIRED_MIGRATION=20261002_0008` hedefine ilerletilir. Eski001–008 geçmişi değişmez; migration grant'leri sağlar. `DATABASE_APP_ROLE`, validated config rolüyle aynı olmalıdır; işlem parent environment'ı değiştirmez. `env.py` yeniden environment URL'si açtığı için bu runner sabit ScriptDirectory/RevisionMap'i Alembic EnvironmentContext üzerinden doğrudan validated admin connection ile çalıştırır. Bütün migration DDL ve head güncellemesi tek PostgreSQL transaction içindedir.

Son kontrol ayrı application credentials ile gerçek bağlantı açar, current/session user'ı, login/privilege/membership kısıtlarını, mevcut application-role grant/RLS kontrollerini ve tam008 head'ini doğrular. Version table oluşturma ve bütün head okumaları açıkça `public.alembic_version` kullanır; database/role `search_path` başka bir schema'nın version table'ını seçemez. Bütün owned connection/pool'lar kapanır. CLI başarıda yalnız `Runtime migration complete`, hatada yalnız `Runtime migration unavailable` yazar ve nonzero döner; DSN, private path veya exception/SQL ayrıntısı yazmaz. Migration hatası transaction DDL/head değişikliklerini geri alır; daha önce ayrı transaction ile oluşturulan kısıtlı rol kalabilir. Son application kontrolü başarısızsa migration zaten commit olmuş olabilir: hata startup'ı durdurur; downgrade veya otomatik grant/role onarımı yapılmaz. Aynı kabul edilmiş release ile tekrar çalıştırma mevcut008 şemayı ileri/geri değiştirmez ve mevcut rol password'ünü korur.

Migration başarıyla bittiğinde API/worker başlatılır, `/ready` ve gerçek auth/project/preparation akışları doğrulanır. Worker handler henüz unconfigured olduğundan runtime ready araştırma pipeline'ının tamamlandığı anlamına gelmez. Yerel disposable PostgreSQL testleri fresh/current/repeat, grant/RLS ve failed transaction davranışını doğrular; bunlar gerçek Hetzner kurulumu, Linux secret mount/UID, SCRAM wire auth veya backup/restore kabulü değildir. Bootstrap'ın bağımsız review/verify kapıları consumer integration öncesinde tamamlanmalıdır.

PostgreSQL local/host başlangıç authentication'ı SCRAM'dir. Container OS kullanıcısı `postgres`, DB admin kullanıcısı `demandrift_admin` olduğundan local peer eşleştirmesi init script'inin bağlantısını engeller. [Resmi PostgreSQL Docker entrypoint'i](https://github.com/docker-library/postgres/blob/master/16/bookworm/docker-entrypoint.sh) init sırasında FILE password'u alıp local authenticated setup için kullanır. Redis health password'u argüman yerine stdin'den alır; [Redis7.4 CLI kaynağı](https://github.com/redis/redis/blob/7.4/src/redis-cli.c) `--askpass` intake'ını tanımlar. Host gerçek init/auth/health davranışı kurulum kabulünde ayrıca çalıştırılır.

Dağıtım helper'ı henüz API-only davranır. Bu dosya o helper ile doğrudan gönderilmez: migration öncesi backup/quiesce, uyumlu image seçimi, admission kapıları ve hata sonrası güvenli toparlama ayrı OP-04 teslimidir. Migration downgrade veya head007 imajına otomatik dönüş, yeni head008 güvenlik koşulunu bozar ve rollback olarak kullanılamaz. DB/raw/spool restore ve gerçek container restart/recovery kabulü OP-05/OP-06'da açık kalır.
